## 1. 구성

```
[GitHub]  ichi7365/ICHI-company-homepage      코드 보관
    │  push 하면 자동 빌드 · 배포
    ▼
[Cloudflare Worker]  ichi-company-homepage   사이트 + API (주소 하나)
    ├─ /api/*  → worker/ 코드 ── D1 (ichi-homepage-db)     회원 · 채용공고 · 문의 · 게시판
    │                         └─ R2 (ichi-homepage-files)  게시글 이미지 · 첨부파일
    └─ 그 외   → out/ 정적 페이지 (Next.js 정적 export)
```

- 페이지와 API 가 **같은 주소**라 CORS 설정이 필요 없고, 로그인은 HttpOnly 쿠키로 처리합니다.
- 브라우저는 D1 · R2 에 **직접 접근할 수 없습니다.** 모든 조회 · 변경은 Worker 가 권한을 확인한 뒤 처리합니다.
- 정적 페이지 요청은 Worker 코드를 실행하지 않습니다(`run_worker_first: ["/api/*"]`). 무료 사용량을 아낍니다.

공개돼도 되는 값은 `wrangler.jsonc` 의 `vars` 에 있습니다 (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `INQUIRY_TO`).

**비밀값은 Worker → Settings → Variables and secrets 에 Secret 으로 등록**합니다.
(예전에는 "정적 자산 전용 Worker" 라 이 메뉴가 막혀 있었는데, 이제 Worker 코드가 있어 열립니다.)

| 이름 | 값 | 필수 |
|---|---|---|
| `SMTP_PASS` | `SMTP_USER` 계정의 하이웍스 비밀번호 | ✅ (없으면 가입 인증번호 · 문의 알림 메일이 안 나감) |

## 3. 서버 코드 (worker/)

`src/app/api/` 는 정적 export 라 동작하지 않습니다. 서버 코드는 전부 `worker/` 에 있습니다.

| 주소 | 하는 일 | 권한 |
|---|---|---|
| `POST /api/auth/email-code` · `/verify` | 가입 인증번호 발송 · 확인 | 누구나 (횟수 제한) |
| `POST /api/auth/signup` · `/login` · `/logout` | 가입 · 로그인 · 로그아웃 | 누구나 (횟수 제한) |
| `GET /api/auth/me` | 로그인 상태 | 누구나 |
| `POST /api/auth/password-reset` · `/confirm` | 비밀번호 재설정 (화면 미연결) | 누구나 |
| `PATCH /api/me` · `POST /api/me/password` · `DELETE /api/me` | 내 정보 수정 · 비밀번호 변경 · 탈퇴 | 로그인 |
| `GET /api/jobs` | 채용공고 목록 | 누구나 |
| `POST /api/inquiries` | 문의 접수 + 담당자 알림 메일 | 누구나 (허니팟 · IP 제한 · Turnstile) |
| `GET /api/posts` · `/api/posts/:id` | 게시글 목록 · 상세 (공개 글만) | 누구나 |
| `GET /api/files/<key>` | 이미지 · 첨부 (공개 글의 파일만) | 누구나 |
| `/api/admin/*` | 채용공고 · 게시글 CRUD, 파일 업로드 · 삭제, 회원 · 문의 관리 | **관리자** |

**보안 원칙**

- `/api/admin/*` 는 들어오자마자 **서버가 DB 의 role 로 관리자 여부를 다시 확인**합니다. 화면의 관리자 가드는 편의 기능입니다.
- 회원이 보내는 `role` · `status` · `email` 값은 무시합니다(권한 상승 방지).
- SQL 은 전부 `prepare().bind()` — 사용자 입력을 SQL 문자열에 이어 붙이지 않습니다.
- GET 이 아닌 요청은 같은 주소(Origin)에서 온 것만 받습니다 + 쿠키 `SameSite=Lax` (CSRF 방지).
- 업로드: 확장자 + 실제 파일 앞부분(매직바이트) 확인, 이미지 5MB · 첨부 20MB, svg · html · exe 거절.
- 비공개 글 · 아직 글에 붙지 않은 파일은 관리자만 볼 수 있습니다(그 외에는 404).
- 비밀번호는 PBKDF2-SHA256 해시, 세션 토큰은 SHA-256 만 DB 에 저장합니다.

## 5. 데이터베이스

스키마는 `migrations/` (D1 = SQLite). 바꿀 때는 새 번호 파일(`0002_…sql`)을 추가하고 `db:migrate:*` 를 실행합니다.

| 테이블 | 쓰이는 곳 |
|---|---|
| `profiles` | 회원 (로그인 계정 겸용, 비밀번호 해시 포함) |
| `sessions` · `email_codes` · `throttle` | 로그인 세션 · 인증번호 · 횟수 제한 |
| `jobs` | 인재채용 (배열 컬럼은 JSON 문자열) |
| `inquiries` | 문의하기 |
| `posts` · `post_files` | 게시판 (공지사항 `notice` · 회사소식 `news`) · 첨부 (파일은 R2) |

**관리자 지정** — 가입 후

```bash
npx wrangler d1 execute ichi-homepage-db --remote --command "UPDATE profiles SET role='admin' WHERE email='admin@ichi.kr'"
```

**비밀번호 해시와 무료 플랜 CPU 한도**

무료 Worker 는 요청당 CPU 10ms 가 한도인데, 비밀번호 해시(PBKDF2 10만 회)가 이를 넘을 수 있습니다.
운영 배포 후 로그인이 가끔 실패(1102 오류)하면 둘 중 하나를 하세요.

- Workers 유료 플랜($5/월) — 가장 확실합니다.
- Secret `PBKDF2_ITERATIONS` 를 낮춤(예: 30000). 기존 해시는 그대로 로그인되고, 다음 로그인 때 새 값으로 바뀝니다.

## 8. 메일 발송 계정

DNS 는 건드리지 않습니다. SMTP 발송은 계정 로그인만 하므로 MX · SPF 와 무관하며,
`ichi.kr` 의 SPF 에 이미 `include:_spf.hiworks.co.kr` 이 있어 스팸 처리 위험도 낮습니다.

대표 메일을 발송 계정으로 그대로 씁니다 (`wrangler.jsonc` 의 `SMTP_USER`, 2026-10-12 결정).

```
SMTP_USER    ichi@ichi.kr   보내는 계정
INQUIRY_TO   ichi@ichi.kr   알림 받는 곳
```

- ⚠️ **대표 메일 비밀번호를 바꾸면 Secret `SMTP_PASS` 도 다시 등록하세요.** 안 그러면 가입 인증번호 · 문의 알림이 끊깁니다.
- 하이웍스 발송 한도를 대표 메일과 같이 씁니다. 나중에 분리하려면 전용 계정(예: `web@ichi.kr`)을 만들어
  `SMTP_USER` 와 `SMTP_PASS` 만 바꾸면 됩니다.

하이웍스에서 **계정별 '외부 메일 프로그램(SMTP) 사용'** 이 허용돼 있어야 발송됩니다.
메일은 Worker 가 `smtps.hiworks.com:465` 에 직접 접속해 보냅니다(`worker/lib/mail.ts`).

**하이웍스 설정 시 주의 (2026-10-12 확인)**

- 메일 환경설정 → POP3/SMTP: **사용 함**, 허용 국가 **모든 국가 허용** (Cloudflare 는 해외 IP 로도 접속합니다)
- **메일 전용 비밀번호가 만들어져 있으면 로그인 비밀번호로는 SMTP 가 거절됩니다**(`535 authentication failed`).
  Secret `SMTP_PASS` 에는 전용 비밀번호가 있으면 그것을, 없으면 로그인 비밀번호를 넣으세요.
- 비밀번호를 연달아 틀리면 하이웍스가 Cloudflare 쪽 접속을 한동안 막는 것으로 보입니다(접속 인사조차 오지 않음).
  틀렸을 때는 바로 재시도하지 말고 30분 이상 기다리세요.
- 실패하면 Worker 로그에 `[mail] 실패 단계 기록: 접속 Nms → EHLO … ` 처럼 어느 단계에서 막혔는지 남습니다
  (`npx wrangler tail ichi-company-homepage` 또는 대시보드 → Observability).

## 9. 도메인 (마지막 단계)

`ichi.kr` 은 현재 유호스트 네임서버(ns1/ns2.uhost.co.kr)에서 운영 중이며 **아직 건드리지 않았습니다.**

전환 시 **MX(`mailapp.hiworks.co.kr`) · TXT(SPF) 레코드는 절대 변경하지 마세요.** 회사 메일이 끊깁니다.
A / CNAME 레코드만 Cloudflare 쪽으로 바꾸는 방식을 권합니다.

도메인을 붙일 때 함께 바꿀 곳

| 곳 | 빠뜨리면 |
|---|---|
| Cloudflare Worker → Domains → Custom domain | `ichi.kr` 로 들어와도 사이트가 안 뜸 |
| `.env.production` 의 `NEXT_PUBLIC_SITE_URL` | sitemap · OG 이미지 주소가 옛 주소로 나감 |

(예전의 Supabase Redirect URLs · Edge Function `ALLOWED_ORIGINS` 는 더 이상 필요 없습니다.
페이지와 API 가 같은 주소라 도메인이 바뀌어도 API 설정은 그대로입니다.)
