## 2026-08-27 (목)

### 문의하기 알림 메일 — 하이웍스 SMTP 연동 완료

Edge Function 을 배포하고 메일 발송까지 연결했습니다. 여섯 단계에서 순서대로
막혔고, 각각 원인을 특정해 해결했습니다. 같은 문제가 재발하면 아래를 보세요.

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | `invalid char found in FQDN` | 대시보드에 값 붙여넣을 때 **공백**이 섞임 | 코드에서 env 값 trim |
| 2 | 20초 무응답 | 서버 주소가 **2019년 종료된 옛 서비스**용 | `smtps.hiworks.com:465` 로 교체 |
| 3 | `Cannot encode string ... Latin1` | **비밀번호에 전각 문자** (한글 입력 상태로 타이핑) | 진단 로그로 특정 → 비밀번호 재설정 |
| 4 | `535 Access denied` | 계정별 POP3/SMTP 설정 · 비밀번호 | 하이웍스에서 재설정 |
| 5 | 메일 원문이 그대로 노출 | 긴 한글 제목을 접을 때 규격 위반 | **제목을 영문으로** 고정 |
| 6 | 본문 끝 글자 깨짐 | quoted-printable 이 한글 중간에서 줄바꿈 | 본문을 **base64** 로 직접 인코딩 |

**2번이 특히 함정이었습니다.** `smtp.hiworks.co.kr` 도 DNS 는 응답하기 때문에
조회만으로는 옛 주소인지 알 수 없습니다. 하이웍스 매뉴얼을 봐야 구분됩니다.

**3번은 진단 로그가 결정적이었습니다.** host/user/pass/to 각각에 Latin1 범위
밖 문자가 있는지 boolean 으로 찍어보니 `pass=true` 로 바로 드러났습니다.

### 코드 설계

- 발송 실패해도 **접수는 성공 처리** — 방문자 화면에 메일 오류가 보이지 않습니다
- 발송 타임아웃 20초 — 메일 서버가 응답하지 않아도 요청이 멈추지 않습니다
- 단계별 로그 (연결 시작 / 값 점검 / 발송 시작 / 성공)

### 검증

```
DB 저장          정상
허니팟           봇 요청 차단
IP 도배 제한     10분 3건 초과 시 429
메일 발송        표·한글·레이아웃 정상 수신 확인
```

### 회원가입 인증을 휴대폰 → 이메일로 변경

휴대폰 문자 인증은 **발신번호 사전등록**(전기통신사업법 제84조)이 필요합니다.
업체 선정과 서류 절차가 걸려 있어, 당장 가능한 이메일 인증으로 먼저 열었습니다.

Supabase Auth 의 이메일 OTP 를 그대로 씁니다. 문자 발송비도 들지 않습니다.

### 가입이 안 되던 문제 — 원인은 자체 코드 버그

증상: 인증은 통과하는데 가입 단계에서 **"이미 가입된 이메일입니다"**.
Supabase 에서 계정을 지우고 다시 시도해도 똑같이 재현됐습니다.

원인 추적 과정입니다.

| 단계 | 확인 내용 |
|---|---|
| 1 | 남겨진 회원정보 때문이라 추정 → SQL 조회 |
| 2 | 조회 결과 계정·회원정보가 **둘 다 있음** → 추정 틀림 |
| 3 | **이름이 "회원"** — 입력값이 아닌 코드의 기본값인 것을 발견 |
| 4 | `getCurrentProfile` 이 로그인 시 회원정보를 **자동 생성**하고 있었음 |

인증 버튼을 누르는 순간 로그인 상태가 되고, 그때 회원정보가 저절로 만들어져
정작 가입 단계에서 중복으로 막히는 구조였습니다. **계정을 지워도 반복될
수밖에 없었습니다.**

조치 — 두 겹으로 막았습니다.

- `getCurrentProfile` 의 자동 생성 제거. 생성은 **`completeSignUp` 한 곳에서만**
- `completeSignUp` 을 `insert` → `upsert` 로 변경.
  인증만 하고 창을 닫아도 다음에 정상 가입됩니다

> **교훈 — "없으면 만들어준다"는 편의 기능이 원인이었습니다.**
> 로그인 경로에는 편했지만 가입 경로와 충돌했습니다.
> 데이터를 만드는 지점은 한 곳으로 몰아두는 편이 안전합니다.

> **진단이 한 번 빗나갔습니다.** DB 흔적만 보고 추정했다가 틀렸고,
> "이름이 입력값과 다르다"는 **데이터 내용**을 보고서야 잡혔습니다.

### 발견한 문제와 대응

**1. Supabase 기본 메일 발송 제한**

```
429  over_email_send_rate_limit
```

무료 플랜 기본 메일은 시간당 몇 통만 가능합니다. 회원이 몰리면 가입이 막힙니다.

- 지금: `Confirm email` 끄고 사용
- 오픈 전: Authentication → SMTP Settings 에 하이웍스 등록 후 다시 켜기

**2. 이메일 확인이 켜진 상태의 가입 처리**

가입 직후에는 세션이 없어 RLS 때문에 `profiles` 행을 만들 수 없습니다.
가입 정보를 auth 메타데이터에 저장하고, 확인 후 첫 로그인 때
`getCurrentProfile()` 이 복원하도록 했습니다. 켜도 꺼도 동작합니다.

**3. Supabase 가 예시 도메인 가입을 거부**

`test@example.com` → `Email address is invalid`. 테스트는 실제 도메인으로.

**4. Cloudflare 환경변수 화면을 쓸 수 없음**

> Variables cannot be added to a Worker that only has static assets.

정적 자산 전용 Worker 라서 실행 시점 변수를 받지 않습니다.
`NEXT_PUBLIC_` 값은 빌드 시점에 박히므로 `.env.production` 으로 해결했습니다.

**5. Supabase API 키 체계 변경**

```
anon         →  Publishable key (sb_publishable_...)
service_role →  Secret key      (sb_secret_...)
```

**DNS 를 바꾸는 순간 유호스트의 기존 홈페이지가 내려갑니다.**
되돌릴 수는 있지만, 전환 시점에 새 사이트가 완성돼 있어야 합니다.

**네트워크 드라이브(Y:)에서는 빌드가 실패합니다.**
webpack 의 심볼릭 링크 처리가 EISDIR 오류를 냅니다.
`npm run dev` / `npm run build` 는 로컬 디스크로 복사해서 실행하세요.

**`src/app/api/` 라우트는 동작하지 않습니다.**
정적 export 방식이라 Next.js 서버가 없습니다.
서버가 필요한 작업은 Supabase Edge Function 으로 처리합니다.

**Cloudflare 프로덕션 브랜치를 확인하세요.**
프로덕션 브랜치가 아닌 곳에 push 하면 `versions upload` 만 실행되어
업로드는 되지만 사이트에 반영되지 않습니다.

**보안 — 새 테이블을 만들 때 RLS 를 반드시 켜세요.**
브라우저가 DB 를 직접 호출하는 구조라 RLS 가 유일한 방어선입니다.
새 프로젝트는 `Enable automatic RLS` 를 켜두었으므로 자동으로 켜집니다.
